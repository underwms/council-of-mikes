# Repository structure

| Path | Purpose |
|---|---|
| `skills/` | Fifteen specialist packages and nine workflows |
| `instructions/` | Shared startup, authorization, memory, and review contracts |
| `adapters/` | Native client pointers and owned configuration fragments |
| `profiles/` | Opinionated example technology policy |
| `rules/` | Global invariants and profile routing |
| `scripts/` | Installer, source checks, memory tools, and Node regression tests |
| `exclusions/` | Explicit source-discovery exclusions |
| `docs/` | Public setup, architecture, verification, and contribution guidance |
| `manifest.json` | Package inventory and distribution boundaries |
| `source-lock.json` | Reviewed source hashes |

Installation creates private `memory/` and `backups/` locally. They are not source payload. Maintenance remains opt-in and workspace-owned. Codex startup offers available maintenance; the agent command checks access before an exclusive daily claim.

No engine, Python runtime, viewer, personal knowledge, legacy archive, or generated build is distributed. The brainstorming visual companion remains an optional skill helper.
