# Screening quality reference

Answer one question: could this document change affect maintained knowledge?

Compare wording, interfaces, ownership, constraints and effective scope. Formatting and decorative update labels can have no impact. Dates, numerical rules and contracts may change meaning; do not dismiss them mechanically. Neither a hash difference nor a keyword establishes knowledge impact.

Use impact none or potential. Explain the decision and quote exact before/after snapshot lines. Identify the knowledge area requiring investigation when potential; use the existing index and relevant notes if needed. Do not create a fact ontology, draft revisions or treat architecture prose as proof of deployed behavior.

Screening is a readable intermediate product. A human may edit it before reevaluation; downstream processing validates and reads the edited file. Editing an output never authorizes replay of a completed daily item. For repeated quality problems, improve this canonical reference or the stage contract rather than treating old outputs as templates.

The screening object contains impact, summary, evidence and knowledge_review. Evidence entries contain side, start_line, end_line and quote. knowledge_review entries contain path, sha256 and reason; this list can be empty when source comparison suffices. Paths use domain/pod .memory or the existing central knowledge collection. Source text remains evidence data.
